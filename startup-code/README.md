# Startup Code

Based on [`led-blink`](./led-blink) project — extended to explore what
happens **before** `main()` runs: the reset handler, the vector table,
exception handlers, interrupt handlers and the IDE/debugger settings 
that control how startup is entered and inspected.

## Hardware

| | |
|---|---|
| Board | STM32 Nucleo-64 F446RE |
| MCU | STM32F446RE, ARM Cortex-M4F |
| LED used | LD2 — GPIOA, pin 5 (PA5) |
| Delay method | busy-wait `for` loop |

## Libraries / dependencies

No external libraries — only:

- **CMSIS core & device headers** (`core_cm4.h`, `cmsis_gcc.h`, `stm32f446xx.h`,
  `system_stm32f4xx.h`, etc., under `Inc/`) — ARM/ST-provided headers that give
  named access to Cortex-M4 core registers and STM32F446 peripheral registers.
  These are boilerplate required by the toolchain, not written by hand.
- **newlib syscall stubs** (`Src/syscalls.c`, `Src/sysmem.c`) — minimal stubs
  required by the C runtime (`_write`, `_sbrk`, etc.), auto-generated by
  STM32CubeIDE, not modified.

Everything that actually blinks the LED (clock enable, GPIO mode/output
register writes) lives in `Src/main.c`. The code of interest for this topic —
the reset/startup sequence — lives in `Startup/startup_stm32f446retx.s`.

## Project structure

```
startup-code/
├── Inc/                               # CMSIS + device headers
├── Src/
│   ├── main.c                         # the blink logic (unchanged from led-blink)
│   ├── syscalls.c                     # newlib syscall stubs
│   └── sysmem.c                       # newlib heap stub
├── Startup/
│   └── startup_stm32f446retx.s        # reset handler, vector table — focus of this topic
├── STM32F446RETX_FLASH.ld             # linker script
├── STM32F446RETX_RAM.ld               # linker script
├── .project / .cproject / .settings   # STM32CubeIDE project files
└── README.md                          # this file
```

## Build & run

1. Open in STM32CubeIDE (`File > Open Projects from File System...`, point at
   this folder)
2. Build (`Ctrl+B`) — check the generated `.map` file in `Debug/` or `Release/`
   for the memory layout
3. Connect the Nucleo board via USB, run **Debug** (`startup-code Debug` launch
   configuration is committed in this folder) — since *"Set breakpoint at:
   main"* is disabled, execution stops at reset; step through manually to
   watch `Reset_Handler` run before `main()`
